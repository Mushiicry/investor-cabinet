# GOLD/XAUT: пропущенный swap 2026-09-23

Статус: диагностика на чтение; production-данные, Apps Script и deploy не менялись.

## Проверенные факты

- BNB Chain tx `0x886a3fb12e5664b2844fcc76cfd9245d660e71b699f6747cd8f0fb2a738f5636` успешна, блок `123520447`, 09:53:37 МСК. В её `Transfer` logs кошелёк отправил `7.525342 + 22.576026 = 30.101368 USDT` и получил `0.001736 + 0.005207 = 0.006943 XAUT`.
- `BNB_WALLET_BALANCES`: между снимками 09:49:13 и 09:54:12 `GOLD` вырос с `0.005686` до `0.012629`; `USDT BNB` в обоих снимках равен `0`. Приход и расход USDT произошли внутри одного интервала синхронизации.
- `Расчеты!GOLD` при чтении: quantity `0.012629`, avgEntry `3517.4111853675695`, invested `44.421385860007035`. Исходная база до swap: `0.005686 × 3517.4111853675695 = $20`.
- В последних строках `Транзакции_IMPORT` есть вывод `30.2 USDT` из Arbitrum, но нет записи покупки GOLD по указанной BNB-транзакции.

## Причина

`IC_BNB_classifyDeltas_` в `apps-script/bnbWalletImport.gs` признаёт покупку GOLD только при одновременных `stableSpent > 0.5` и `goldDelta > 0`. Балансовые снимки не видят промежуточный USDT, поэтому quantity обновляется, а audit row и средний вход нет.

## Предлагаемое исправление после разрешения владельца

1. Зафиксировать транзакцию по полному tx hash в `Транзакции_IMPORT` без дубля и со ссылкой на два входящих и два исходящих `Transfer`.
2. Установить для GOLD cost basis `$50.101368` и avgEntry `50.101368 / 0.012629 = $3967.1682635204684` (значение D хранить с достаточной точностью; E остаётся формулой `C*D`). Сверить агрегаты и API после записи.
3. Исправить импорт так, чтобы изменение GOLD без видимой стейбл-пары не проходило молча: оставить его на проверку по tx evidence и применять cost basis только при установленной паре. Проверить случай bridge + swap между снимками и идемпотентность.

`docs/HANDOFF.md` закрепляет `apps-script/**` за Claude; изменение этой зоны, source of truth в Google Sheet и production-публикация требуют отдельного решения владельца.
