# Design System

## Design Mission

The interface must help investors think clearly.

The interface is not entertainment.

The interface is not a trading platform.

The interface is not a crypto casino.

The interface exists to reduce stress, improve clarity and support intelligent decision making.

At the same time it should feel friendly, immersive and pleasant — something the investor enjoys looking at and wants to return to. Calm, not cold. Premium, not sterile.

# Glow & Motion Rules

Restrained neon glow, electric current / flow lines, and subtle pulsing / breathing are part of the signature style. They are encouraged when they are calm, slow and purposeful.

Allowed (the signature):

* soft neon glow on key elements (one cold accent)
* electric current / flow lines (e.g. energy moving toward the Health core)
* slow pulsing / breathing of the core and indicators
* gentle starfield / space ambiance (no bright stars, light dust)
* smooth, slow transitions and hover feedback

Forbidden (keeps it stylish, not cyberpunk):

* garish, multi-color "rainbow" neon
* blood-red / heavy-purple cyberpunk overload
* flashing, strobing, fast or aggressive motion
* dopamine / casino triggers
* meme-finance and trader-gambling aesthetics
* glow or motion with no purpose
* unnecessary charts, indicators and decorative widgets

Rule of thumb: restrained but stylish. Atmosphere supports focus — it never competes with the data.

# Typography

Typography should feel:

* professional
* premium
* readable
* structured

---

# Color Philosophy

Colors should communicate meaning.

Not decoration.

Color usage should be intentional.

Risk colors must be consistent.

Status colors must be consistent.

Do not introduce random colors.

Base: one deep dark tone (near-black with a slight cold blue), unified across the whole app and matching the Health core background — no visible seams, no grid.

Accent: a single cold axis (icy cyan / blue). Avoid many competing bright colors.

Risk / status colors (green / amber / red) are used only to signal — never as decoration.

Keep the palette minimal: color carries meaning, glow carries focus.

The dashboard should not overwhelm the investor.

---

# Protected Layout Rule

Preserve approved UI geometry.

Do not redesign layouts automatically.

Do not move major sections without explicit instruction.

Do not replace existing structures because of design trends.

Working layouts have priority over redesigns.

---

# Health Block Protection

The left-side Health block on the Risk screen is protected.

This block has been explicitly approved.

Do not redesign.

Do not relocate.

Do not remove.

Only modify if explicitly requested.

---

# Market Psychology Engine

This module is strategic.

Purpose:

Visualize market emotional state.

Purpose is not prediction.

Purpose is investor guidance.

The module should feel:

* institutional
* intelligent
* analytical

Never theatrical.

Never sensational.

Never casino-like.

---

# Gamification Rules

Gamification is allowed.

Casino psychology is forbidden.

Gamification should reward:

* discipline
* consistency
* risk management
* portfolio health
* long-term investing

Gamification should never reward:

* excessive trading
* leverage
* impulsive behavior
* gambling

---

# Component Philosophy

Components should feel:

* modular
* premium
* minimal
* information-dense

Avoid empty decorative space.

Avoid clutter.

Balance density with readability.

---

# Design Decision Rule

Before changing any screen ask:

Does this improve clarity?

Does this improve decision quality?

Does this improve risk visibility?

Does this improve usability?

If not, keep the current design.

---

# Final Design Principle

The product should feel like a system for managing millions of dollars.

Not a tool for chasing excitement.
